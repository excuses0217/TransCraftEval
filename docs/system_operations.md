# 映鉴部署维护手册

本文面向本地系统维护人员。命令默认在项目根目录执行，`python` 指已选择的 Python 3.12+ 解释器。一键入口针对 macOS，其他操作系统尚未完成验收。

## 1. 运行结构

静态前端、API、默认素材和证据文件由同一个 FastAPI 服务提供；后台线程执行 YuNet + SFace 人物检索，`imageio-ffmpeg` 提供视频转码程序。不依赖云端 API、LLM、Node 服务、外部数据库或在线视频下载。

系统没有身份认证、多租户、角色权限和分布式恢复能力，只监听 `127.0.0.1`，不要直接暴露到公网。不要启用多 worker 或多个进程写同一状态文件。生产/验证空间是服务端按任务用途筛选的业务边界，不是账号权限隔离。

| 运行方式 | 端口 | 状态文件 | 运行输出 |
| --- | --- | --- | --- |
| 一键演示，showcase 配置 | 默认 8770 | `data/showcase/state.json` | `artifacts/showcase/` |
| 原整片环境，非 showcase 配置 | 本机既有 8766 | `data/media_review_state.json` | `artifacts/` |
| 旧脚本 run_prototype.sh | 默认 8765 | 同原整片环境 | 同原整片环境 |

端口不决定数据隔离。把演示端口改成 8771 仍使用同一演示状态，不能作为独立实例并行写入。旧 8765 入口与原 8766 环境也不能同时写原状态。

## 2. 环境准备与启动

需要 Python 3.12+、项目依赖及两个 ONNX 模型；`showcase_bundle/` 为可选内置素材包，没有包也能启动并导入自己的 MP4。依赖在 `pyproject.toml` 固定版本，模型脚本校验 SHA-256。首次安装需网络及 `curl`、`shasum` 等命令，日常素材和模型齐全后可离线运行。

在选定的虚拟环境中准备依赖：

```bash
python --version
python -m pip install -e '.[test]'
sh scripts/download_models.sh
./scripts/start_showcase.sh
```

macOS 也可双击 `start.command`，默认打开[算法验证大盘](http://127.0.0.1:8770/?workspace=validation#/overview)。

解释器选择顺序：显式指定 → 合格的 `.venv` → 本机 `~/miniconda3/envs/transcrafteval` → 合格的 `.showcase-venv` → 用合格的 `python3` 创建 `.showcase-venv`。均需满足 3.12+，不要覆盖系统旧 Python。启动时的模块导入检查不是完整版本一致性检查，迁移时应按项目依赖安装。

| 环境变量 | 用途 |
| --- | --- |
| `FACE_WATCH_PYTHON` | 指定 Python 可执行文件完整路径 |
| `FACE_WATCH_PORT` | 修改端口，默认 8770；不改变状态目录 |
| `FACE_WATCH_NO_BROWSER=1` | 不自动打开浏览器 |
| `FACE_WATCH_CHECK_ONLY=1` | 仅显示配置路径；不检查素材、依赖或模型完整性 |

```bash
FACE_WATCH_PYTHON='/absolute/path/to/python' ./scripts/start_showcase.sh
FACE_WATCH_NO_BROWSER=1 ./scripts/start_showcase.sh
FACE_WATCH_CHECK_ONLY=1 ./scripts/start_showcase.sh
```

目标端口已有可响应的 showcase 服务时会复用；其他服务占用时退出，不杀掉原进程。当前复用只核对 profile，不区分不同项目副本，维护人员应人工核对实际目录。

保留首次启动终端，停止时按 Ctrl+C；关闭浏览器页签不会停止服务。停止前等待检查完成，进程中断的任务不能自动续跑，重启后显示检查未完成，可重新执行，但不会从中断帧续算。

旧兼容入口：

```bash
./scripts/run_prototype.sh '/path/to/video.mp4' '/path/to/reference.jpg' '人物名称' 8765
```

旧脚本直接使用 `.venv`，没有新版解释器筛选。零参数使用 `examples/sample.mp4`、`examples/reference.jpeg`，标签为“目标人物（老许）”，不是完整默认包入口。不要与既有原环境并行写入。

## 3. 目录与数据生命周期

| 路径 | 内容 |
| --- | --- |
| `frontend/` | React、TypeScript、Vite 与 Tailwind 前端源码；开发和发布构建使用 |
| `frontend_dist/` | 已构建的静态界面；日常启动无需 Node.js |
| `src/face_watch/` | API、人物检索、默认包加载逻辑 |
| `showcase_bundle/clips/` | 默认短视频 |
| `showcase_bundle/references/` | 全部保留参考照片，含停用素材 |
| `showcase_bundle/evidence/` | 默认任务证据及参考图快照 |
| `showcase_bundle/catalog.json` | 媒资名称、位置、时长和任务关联 |
| `showcase_bundle/seed.json` | 首次初始化对象与任务，不保存后续人工决定 |
| `data/showcase/state.json` | 当前演示状态、审核结果与历史 |
| `artifacts/showcase/` | 新任务输出、上传照片和预览缓存 |
| `artifacts/showcase/media/` | 用户导入视频，按内容摘要命名；不是可随意清理的缓存 |
| `models/` | 本地模型；ONNX 文件被 Git 忽略 |
| `媒资/` | 本机原片，Git 忽略；默认片段运行不依赖它 |
| `output/` | 验收报告和实验输出，Git 忽略 |

应用逻辑不修改默认包，但它没有被文件系统锁定为只读。首次启动创建空白状态并显示引导，用户确认后才导入 seed；已有旧工作空间自动保留原素材目录。后续以已保存状态为准，替换 seed 不会自动升级已有库与任务。重复导入按对象、任务和媒资 ID 只添加缺项，不覆盖修改。

状态文件保存 `media_items`、`workspace_initialized`、人物验证状态/生命周期和审核版本快照。本地视频导入按 SHA-256 去重，检查文件扩展名和视频可解码性，逐文件保存；不把上传完成误当作识别完成。上传会产生临时文件和本地副本，大文件导入应预留足够磁盘空间。

默认包使用相对路径，加载时转换成当前目录的绝对路径。已保存运行状态包含绝对路径，因此迁移初始默认包与迁移已有审核进度不是同一操作。

## 4. 交付、备份与恢复

### 新机器启动初始默认内容

1. 交付 `pyproject.toml`、`src/`、`frontend_dist/`、`scripts/`、`start.command`、文档及完整 `showcase_bundle/`。
2. 可复制已校验的 `models/`，避免重新下载。
3. 不复制个人 `.env`、密钥、`data/`、运行缓存或虚拟环境；新机安装依赖。
4. 启动后在引导中选择内置素材或自己的视频，再执行验收。默认结果展示不需要整部电影。

当前分支为 `codex/local-review-showcase`；创建分支不代表工作区已提交、推送或打包。交付前检查 `git status --short`，核对代码与素材是否完整，不能仅发送分支名。原整片不要误加入普通代码提交。素材对外演示或分发前另行确认使用权限。

### 保留审核进度

停止服务后，成套备份默认包、对应状态文件、对应运行输出，以及用户额外引用的视频与照片。备份带日期、限制访问，不包含密钥。

同机同路径恢复时，先保留现状副本，再从匹配备份恢复并核对任务和媒体。跨机器或改变目录时，需校验并迁移绝对路径；当前没有自动迁移工具，不能只复制 JSON 就承诺恢复成功。

### 恢复初始演示状态

先明确恢复意图，停止服务并备份。将 `data/showcase/state.json` 移至独立的带日期备份位置，再重新启动，显示首次导入引导；选择导入内置包才会恢复初始内容。此后界面不再显示原人工修改和上传目录索引，但可用备份恢复。保留相关运行输出，不直接删除目录，不操作原环境状态文件。

以上是维护流程说明，不会自动执行。不要在运行中手动编辑状态 JSON。

## 5. 默认包构建

`scripts/build_showcase.py` 是维护工具，正常启动不调用。它需要原 `data/media_review_state.json`、被引用的视频和照片、模型及识别依赖。

流程为：读取对象与候选任务 → 每个视频选最多两个不重叠窗口 → 本地转码 → 重新执行人物检查 → 保存证据、目录与初始任务。停用照片仍保留但不参与检索。

仅在目标工作副本没有完整 `showcase_bundle/seed.json` 时执行：

```bash
python scripts/build_showcase.py
```

已有完整包时拒绝覆盖。更新包应先备份，在单独工作副本构建、验收，再替换；不要删除使用中的 seed 强行重建。中间结果会缓存，改变参考图、模型或算法后应使用新的工作副本，不能把旧缓存当作新实验结果。

## 6. 验收

前端源码变更后，使用 Node.js 20+ 与 pnpm 构建；构建保留 `frontend_dist/assets/references/`，不能清空历史参考图片：

```bash
cd frontend
pnpm install
pnpm build:clean
cd ..
```

`pnpm build` 会保留旧的带哈希分包，适合开发期间增量构建；正式交付使用 `pnpm build:clean` 生成整洁产物。执行清理构建前必须停止服务或使用原子目录切换，不要在仍有审核员打开旧页面时删除旧分包，否则旧会话的按需页面可能无法继续加载。

自动化测试：

```bash
python -m pytest -o addopts='' -q
```

2026-09-19 的导入功能验收基线为 42 项通过、1 项跳过，含空白初始化、跳过与重启、文件校验、与内置视频去重、旧状态迁移和重复导入不覆盖审核记录。跳过不等于已验证；后续交付以当次输出为准。

启动默认 8770 服务并导入内置包后检查真实素材和预览接口：

```bash
python scripts/check_showcase.py
```

脚本固定访问 8770，不读取自定义端口。检查媒资、参考图、证据、时间范围，以及各默认任务首条候选的预览和视频 Range 响应。生成预览缓存及 `output/showcase-check.json`，不改人工标签。接口通过不等于全部视频已人工逐帧检查。

界面验收清单：

- 审核大盘、工作台、任务中心、媒资中心、对象库和结果中心使用同一工作空间口径，指标可进入对应业务页。
- 12 个默认片段可搜索和播放。
- 人物库保留 14 人、24 份素材及其中 2 份停用照片。
- 初始 12 个验证任务合计 82 条未处理候选；人工处理后的运行状态不要求仍为此数。
- 从媒资卡片创建任务自动带入文件，可多选人物；未接入能力不可执行。
- 专注复核页可自动准备并播放上下文、查看参考快照、记录原因；未解决疑点阻止完成。
- 桌面三栏复核和 390px 窄屏纵向复核中，返回、视频、候选、参考照和判定按钮均可到达。
- 重启保留修改，不重复导入；原整片环境不受影响。

上述工程验收不能推导准确率、召回率或误报率，识别效果仍需独立标注实验。

## 7. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 打开后还是 8766 旧任务 | 使用 8770 完整入口，两套运行数据不自动同步 |
| 人物不能选入生产任务 | 检查是否待验证；先验证，不批量启用绕过门禁 |
| 内置素材不可用 | 可以先导入自己的 MP4；需内置内容时复制完整 seed、目录、视频和照片 |
| Python 版本过低 | 用 FACE_WATCH_PYTHON 指向 3.12+，不覆盖系统 Python |
| 模型下载或校验失败 | 检查网络、代理和模型完整性，不跳过校验 |
| 端口被占用 | 核对进程，必要时改端口；仍不能多进程写同一状态 |
| 预览失败 | 检查路径、磁盘和 FFmpeg；暂看截图并留待复核，不能据此确认身份 |
| 参考图不可用 | 检查清晰度、单脸和停用状态，补充照片后建新任务 |
| 换照片后旧结果没变化 | 旧结果使用快照，需重新创建任务对比 |
| 文件移动后不能播放 | 恢复路径或创建指向新路径的任务，不随意移动默认包 |
| 状态 JSON 损坏拒绝启动 | 保留损坏原件，从匹配备份恢复，不用空文件覆盖 |

日志输出到启动终端。当前没有统一日志平台、自动备份、任务调度器或多实例互斥管理。
