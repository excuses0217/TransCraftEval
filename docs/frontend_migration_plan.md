## 3. 新产品形态与工作流程

### 3.1 工作对象

产品以五类对象组织：媒资是被审核的视频，审核对象是要查找的人物或内容规则，任务是一次确定范围的检查，线索是需要人工核查的片段，审核结果是任务范围内已经保存的处理记录。

一份媒资可以关联多次任务；一次任务引用多个审核对象，并保存当次参考快照；一个片段的人工判断属于具体任务。重新检查创建新任务，历史结果保持可追溯。页面中的“媒资状态”“任务状态”“片段判断”分别表达，不能合成一个含义模糊的“已审核”。

### 3.2 新导航结构

```text
工作空间：生产审核 / 算法验证
├─ 审核大盘         整体进展、积压、处理趋势与需要关注的任务
├─ 审核工作台       待处理工作与继续复核
├─ 任务中心         建任务、看执行、处理失败、查看任务范围
├─ 媒资中心         导入、检索、预览、查看同一媒资的任务记录
├─ 审核对象库       人物 / 敏感词 / 内容规则，分别管理
└─ 审核结果         按任务范围查询已完成记录与导出

上下文页面：新建任务 / 任务详情 / 媒资详情 / 人物详情
专注工作模式：片段复核
算法验证空间下的次级入口：技术验证工具
```

主导航不再同时保留“工作台、待我复核、审核任务”三个相近列表。工作台负责告诉用户下一步处理什么，任务中心负责管理执行过程，审核结果负责查阅已完成记录。人物、敏感词、内容在审核对象库内拥有独立标签、列表与编辑入口，不混用字段和表单。

审核大盘提供跨任务概览，工作台承接具体待办，两者使用不同的内容组织。普通首次入口进入生产审核大盘，并有醒目的“进入审核工作台 / 继续复核”；直接访问工作台、任务或媒资详情时保持原目标，不强制经过大盘。一键体验入口进入明确标识的算法验证大盘。

空白初始化是大盘和工作台共享的首次准备模块，不作为长期覆盖所有页面的弹窗。旧启动链接通过兼容适配进入对应新页面。

### 3.3 页面职责与主操作

| 产品页面 | 用户要完成的事 | 内容与交互 |
| --- | --- | --- |
| 审核大盘 | 了解整体进展并发现需要处理的问题 | 关键指标、处理趋势、任务状态与结果分布、待恢复任务；点击数字或图表进入对应列表 |
| 审核工作台 | 开始或继续当前待办 | 待处理片段与任务摘要；“开始复核 / 继续复核”主操作；未处理、留待复核筛选；按任务分组 |
| 任务中心 | 管理一次检查的执行与范围 | 表格列出媒资、范围摘要、检查状态、人工进度；状态视图切换；创建、开始检查、失败恢复 |
| 任务详情 | 理解这个任务检查了什么、到哪一步 | 检查范围、执行状态、覆盖情况、人工统计；主操作随状态变化；重跑放在次级操作 |
| 新建任务 | 确定媒资、范围并开始 | 独立步骤页：选媒资 → 选审核对象 → 核对并提交；返回保留输入，明确所属空间与已启用能力 |
| 媒资中心 | 管理和找到视频 | 列表默认展示封面、名称、时长、大小与可核实的关联任务信息；按需预览；导入作为主操作 |
| 媒资详情 | 了解一份视频及其审核记录 | 单个播放器、基本信息、关联任务、创建新任务；不同任务范围分别显示 |
| 人物列表与详情 | 维护可用的核查人物 | 列表看分类、照片数量与状态；详情集中管理基础信息、照片、停用和验证说明 |
| 敏感词 / 内容规则 | 准备后续检测规则 | 各自独立列表与编辑；明确当前仅管理，不参与检测 |
| 专注复核 | 连续看片段并作判断 | 播放为核心，队列、参考照片和判断围绕当前片段；完成后进入任务结果摘要 |
| 审核结果 | 查阅已经完成的记录 | 按任务与媒资检索，查看本次范围、片段记录和导出；修改判断采用显式入口 |
| 首次准备 | 为工作空间加入第一份素材 | 在空白工作台选择自有视频或内置素材，也可跳过；缺少人物时提供明确补充入口 |

媒资、任务、人物详情是可返回、可定位的业务页面。小范围新增/编辑可使用标准弹窗；多步骤任务配置和持续视频复核使用独立页面，避免在大弹窗中嵌套整套工作流程。

### 3.4 四条主要流程

1. **首次准备**：打开工作台 → 导入媒资 → 提示准备核查人物 → 新建任务。导入内置素材后进入验证空间待办，不将体验数据混入生产任务。
2. **发起检查**：在任务中心或媒资详情创建 → 选择一份视频 → 搜索、按分类选择人物 → 核对范围 → 提交。执行器忙碌时任务显示待执行，并给出后续启动入口。
3. **日常审核**：打开工作台 → 继续任务 → 连续播放与判断 → 处理留待复核项 → 核对任务摘要 → 完成本次审核。日常工作无需进入参考图维护或技术验证页面。
4. **结果追溯**：从媒资详情或审核结果进入 → 查看具体任务范围、片段判断与备注 → 导出。重新检查时创建关联任务；纠正人工判断时明确重新打开复核。

每个状态有一个明确主操作，例如任务检查完成后主按钮是“开始复核”，不同时平铺“运行、查看、继续、完成”等互斥动作。所有待办、任务和结果统计先按当前用途隔离。

### 3.5 审核工作台的待办组织

工作台首先展示未处理工作，次要位置展示运行中与需要恢复的任务；大幅指标卡和说明横幅不占据首屏主要空间。没有任务时显示创建引导，有任务但暂无候选时显示相应状态，有刷新错误时保留原数据。

队列可按任务、人物和处理状态筛选，条目包含视频名称、当前核查人物、片段位置、缩略图与处理状态。底层用现有任务中的事件构建视图，以任务 ID + 事件 ID 作为复合主键。跨任务汇总只用于发现待办，进入复核后固定在当前任务内，避免无提示地跳到另一部影片。

首版排序采用“未处理优先、留待复核随后；同任务按时间顺序”，选定条目后保持队列位置稳定。没有风险、任务时限或分派字段时不伪造风险排序、逾期提醒或个人归属。模型相似度和采样率不出现在审核工作区。

### 3.6 专注复核模式

进入复核后收起全局导航，使用任务上下文栏和专用工作区域。宽屏布局围绕三块区域重新设计：窄侧片段队列、主视频区、核查对象与判断区；笔记本可以合并为双栏，窄屏改为纵向。具体比例由 Aumai 组件与实际内容原型验证，不继承旧复核页布局。

- 上下文栏：返回工作台/任务、当前任务与用途、已处理进度；完成按钮在条件满足时可用。
- 片段队列：人物、位置、状态、缩略图；切换未处理/留待复核/全部，定位当前项。
- 主视频区：即点即准备片段，播放/暂停、重播、倍速及实际位置；失败时静帧兜底并提供恢复操作。
- 判断区：核查问题、本次任务参考照片、确认出现/排除/留待复核；原因和备注按需展开，撤回位于已处理条目的次级操作。

参考照片优先使用 `reference_snapshot`，缺失时明确说明；当前人物库照片不能冒充历史依据。由数据支持时显示连续出现等客观提示，不把模型分数翻译成未经标定的“高可信”或提前显示人工确认结论。

判断保存成功后进入当前任务下一条未处理片段；失败停留原片段并保留输入。全部未处理项完成但仍有留待复核项时，引导继续处理，不能直接结束任务。检查覆盖不完整时将该问题提升为任务级状态，明确下一步恢复动作。

快捷键保留空格播放/暂停、左右切片、1 确认、2 排除、3 留待复核、0 撤回。输入框、可编辑区域、下拉菜单、弹窗和播放器自身获得焦点时，不截获其原有按键。未保存备注作为当前会话草稿保留，离开任务时处理好提示与恢复。

“无候选”“人工确认出现”“完成本次审核”分别表达不同事实；任务完成仅针对本次范围。批量确认片段、自动裁决和自动生成整片审核结论不进入本轮重构。

### 3.7 产品原型交付门槛

正式实现前，先产出新信息架构、四条用户流程和关键屏幕：审核大盘、审核工作台、任务中心、新建任务、媒资详情、人物详情、专注复核、结果摘要。关键屏幕使用 Aumai 的真实组件或视觉规范，并展示正常、空白、加载、失败和已完成状态。

验收关注用户是否能够知道当前要处理什么、点击后去哪、结果是否保存、失败后如何继续。旧页面截图只用于核对遗漏功能，不参加新设计风格对照。该阶段可形成可点击前端原型；其中静态数据必须标明仅用于设计评审，正式接入阶段逐项替换为真实接口。

### 3.8 审核大盘

大盘采用 Aumai 同体系的浅色业务面板、紧凑指标卡、标准图表和可操作列表。页面用于回答“现在有多少工作、处理到哪里、哪些任务需要介入”，保持可读、可点击和可下钻。大盘是一项正式交付能力，纳入原型、实现和验收。

桌面页面从上到下组织为：

1. **页头与范围**：审核大盘、当前工作空间、最近更新时间、刷新、进入审核工作台；期间指标可选近 7 天、近 30 天或自定义日期。
2. **当前关键指标**：检查中任务、待复核任务、待处理片段、留待复核片段。标题明确“当前”，不随趋势日期筛选改变。
3. **期间处理趋势**：新增任务与完成任务按日趋势；同一张图共用任务数单位，展示可用日期范围。
4. **当前分布**：任务状态分布、片段人工判断分布；使用横向条形图及明确数量，保留跳转列表的入口。
5. **需要关注**：检查失败、检查覆盖不完整、仍有留待复核片段的任务，显示原因摘要和“查看任务 / 继续复核”等动作。
6. **近期完成记录**：任务、媒资、完成时间、范围摘要，点击打开对应结果；限制行数，完整记录通过结果页查看。

#### 指标口径与数据要求

| 指标 | 定义 | 数据来源与边界 |
| --- | --- | --- |
| 当前检查中任务 | 当前用途中 `status=running` 的任务数 | 任务记录；不等同后台排队数量 |
| 当前待复核任务 | 当前用途中 `status=needs_review` 的任务数 | 零候选但尚待人工完成的任务也可能包含在内 |
| 当前待处理片段 | `pending`（含旧记录缺省值）与 `uncertain` 的候选总数 | 用任务 ID + 事件 ID 去重；留待复核是其子集，不能再相加 |
| 当前留待复核片段 | 人工判断为 `uncertain` 的候选数 | 可下钻到工作台的留待复核视图 |
| 当前结果分布 | 未处理、确认出现、已排除、留待复核四类互斥计数 | 按每条候选的当前状态统计；历史修改次数不重复计入 |
| 当前任务状态分布 | 待执行、检查中、待复核、已完成、失败等互斥任务数 | 旧 `draft` 显式映射为草稿；未知状态列为其他，不静默丢失 |
| 期间新增任务 | `created_at` 在选择期间内的任务数 | 当前任务创建接口未保存该字段，需兼容补充；旧任务无日期时不估算 |
| 期间完成任务 | 当前仍为已完成，且 `completed_at` 在选择期间的任务数 | 现有完成时间可用；重新打开复核后不再计入已完成，图表说明采用当前完成口径 |
| 需要关注任务 | 失败、覆盖不完整或存在留待复核片段的任务集合 | 同一任务可能有多个原因，但只展示一行；不称为“敏感人物风险排行” |

大盘所示“确认出现”是人工判断结果，不代表违规或风险等级。人工确认比例、排除比例不作为算法准确率、召回率或误报率；未建立独立真值前，大盘不展示这些效果指标。缺少人工计时基线时也不显示节省工时、效率提升率或人员绩效。

日期统一按本地配置时区分组，期间边界一致；零条记录与缺失时间分别显示。历史任务无创建/完成日期时，明确标注“部分历史任务缺少日期，未纳入趋势”，保留当前统计；整段无可用数据则展示空态，不补造历史曲线。第一次导入默认包只改变当前库存与待办，不把导入时间充当历史任务创建时间。

#### 数据实现与下钻

- 所有图表、卡片和下钻列表共用统计函数与筛选定义。点击当前指标保留当前用途；点击期间趋势保留用途、日期及日期字段含义，列表明确显示筛选条件。
- 首版从已有任务数据聚合当前指标；为后续新建任务增加 `created_at`，重跑任务记录自己的创建时间。兼容保留已有 `completed_at`，不为旧记录推断缺失时间。
- `/api/overview` 的既有响应保留兼容。客户端聚合足以满足规模时复用同一份数据；数据量增长后再增加轻量汇总接口，避免每次拉取全部证据与历史明细。
- 自动刷新采用单一受控轮询，建议前台 15 秒、后台暂停；支持手动刷新。刷新失败保留上次数据和时间，明确提示暂未更新。
- 系统运行区只展示可观测的分析任务状态和最近成功刷新；需要显示分析器可用性时补真实检查。HTTP 请求成功不自动等于所有检测服务健康。
- 人物、敏感词和内容规则仍为统一对象库管理；暂未接入检测的类别不出现在检测结果图表中冒充已参与审核。

验收必须覆盖：生产/验证隔离；指标与下钻列表一致；撤回和重新完成后的统计变化；日期边界；重复导入；旧日期缺失；断网或刷新失败；零数据；长任务名。时间趋势上线以前先完成必要日期字段，不将展示用数据混入正式大盘。

### 4.2 组件清单与采用方式

| 层级 | 组件 | 采用方式 |

## 5. 工程结构与运行方案

### 5.1 目标结构

```text
frontend/
  package.json / package-lock.json
  vite.config.ts / tsconfig.json / tailwind.config.js
  src/
    app/                 # 路由、工作空间上下文、错误边界
    pages/               # 页面编排
    features/
      dashboard/ tasks/ review/ media/ library/ onboarding/ maintenance/
    components/
      ui/                # 单一基础组件实现
      business/          # 跨页面展示和业务组合
    api/
      http.ts / problem.ts / contracts.ts
      modules/           # tasks、review、media、library、workspace
    hooks/               # useApi、受控轮询等
    lib/                 # cn、时间和数字格式化
    styles/              # 主题与少量全局样式
  public/assets/references/  # 保持现有照片 URL
  tests/                 # 关键状态与交互测试
  docs/                  # 组件采用记录与开发约定
frontend_dist/           # 构建后的发布目录，FastAPI 提供
src/face_watch/          # 现有后端与分析器
```

依赖方向：页面 → 业务功能 → 业务组件 → 基础组件；页面和业务功能 → API 模块 → HTTP 适配。API 模块不依赖 React，不通过全局 DOM 读取表单值。

采用 React、TypeScript、Vite、Tailwind、Radix、CVA、Lucide、Sonner 和用于大盘的 Recharts；版本优先沿用经验证的 Aumai 组合，实施时校验 Node engines 与锁文件并固定可用版本，不顺带升级依赖大版本。图表随大盘路由加载，不增加专注复核页的首屏依赖。

### 5.2 构建与一键启动

- Node/npm 只用于开发和生成前端静态文件。发布包携带已构建文件，用户继续通过 `start.command` / `start_showcase.sh` 启动 Python 服务。
- 迁移开发阶段 Vite 使用独立端口（建议 5175），将 `/api`、`/artifacts`、`/bundled`、`/demo` 代理到选定本地后端；以实际挂载路径为准补齐清单。
- 对比阶段新旧前端可访问同一个 API 服务，但不同时编辑同一条复核记录。禁止启动两个后端进程写同一状态文件。
- 发布前先构建到临时输出目录并验证，再替换发布目录；不能直接清空 `frontend_dist` 导致历史照片消失。
- 将现有静态参考图建立为 `frontend/public/assets/references` 的受控资源，核对文件哈希与 URL 后随构建复制。构建 JS/CSS 放在 `/ui-assets/`，避免与 `/assets/references/` 冲突。
- HTML 不缓存，带哈希的 JS/CSS 可长期缓存；API 保持当前不缓存行为。预览视频保持 Range、类型和缓存访问行为。
- 提供构建版本标识和产物校验；启动器发现已运行旧版本时应提示需要在任务空闲后重启，不静默误报为新版本。
- 全部页面接入完成前，新前端保持开发预览入口，不提前切换用户默认入口。

### 5.3 路由与状态

首版使用 HashRouter 支持静态部署，新路由按产品职责建立：`#/workbench`、`#/tasks`、`#/tasks/new`、`#/tasks/:id`、`#/tasks/:id/review`、`#/media`、`#/media/:id`、`#/library/people`、`#/library/people/:id`、`#/library/terms`、`#/library/content`、`#/results`、`#/results/:taskId`、`#/validation/tools`。

审核大盘使用 `#/overview`，新安装的产品根入口默认指向大盘。保留直达工作台和各业务页的路由；旧 `#dashboard` 仍按其历史工作台含义兼容映射，避免旧书签含义变化。

单独的兼容适配器把旧 `#dashboard` / `#queue` 归入新工作台，将 `#task/:id`、`#tasks`、`#media`、`#reports`、旧库页面与 `#analysis` 映射到对应新入口；解析旧 `?workspace=validation#media`。保留历史可达性不意味着保留旧菜单或页面。

工作空间和列表条件由统一路由适配层维护，返回列表恢复条件。任务用途以服务端记录为准。媒资详情需要稳定媒资 ID：优先采用已有稳定标识；缺失时为媒资记录补充兼容字段和旧记录读取映射，不能把绝对路径暴露为 URL 标识。对象详情可由现有对象列表和 ID 查找构建，暂不为每个新页面新增一套后端接口。

| 状态类别 | 所有者与规则 |
| --- | --- |
| 服务端记录 | API 请求层；保存后使用响应更新，再按需刷新相关列表 |
| 任务/片段标识 | 路由和复核模块；用稳定 ID，不能用列表下标承载身份 |
| 工作空间 | 应用层；切换时清理旧请求，不能用旧用途数据填充新页面 |
| 搜索、筛选、分页 | 路由参数或页面状态；返回时恢复；不保存绝对文件路径到 URL |
| 表单和备注草稿 | 当前功能模块；保存前不写全局服务端缓存 |
| 播放器、预览请求 | EvidencePlayer；切换片段后取消/忽略旧响应，离开页面暂停播放 |
| 派生统计 | 当前用途下的任务/片段记录计算；不维护第二份独立可写计数 |

首次使用轻量 `useApi` 和受控轮询，复用 Aumai 的取消与过期响应保护方式。没有跨页面复杂缓存需求时不引入全局 Store 或第二套查询框架。

## 6. API 接入清单与业务边界

### 6.1 现有接口映射

| 功能 | 现有接口 | 接入注意事项 |
| --- | --- | --- |
| 配置与初始化 | `GET /api/settings`、`GET /api/workspace/setup` | 区分运行 profile、初始化开关和实际检测能力 |
| 默认导入 / 跳过 | `POST /api/workspace/import-defaults`、`POST /api/workspace/skip` | 已有状态优先；重复导入不覆盖 |
| 媒资 | `GET /api/local-media`、`POST /api/media/import` | MP4、20GB 限制、内容去重；逐文件结果和失败重试 |
| 对象库 | `GET/POST /api/library-items`、`PUT /api/library-items/{id}` | 保留 ID 和类型不可改；使用实际状态枚举 |
| 参考图 | `GET/POST /api/library-items/{id}/materials`、`POST .../upload-reference`、`PATCH .../materials/{material_id}` | 图片质量错误就地显示；停用/恢复不改历史快照 |
| 总览 / 任务列表 | `GET /api/overview`、`GET /api/review-tasks` | 当前返回所有用途，展示层先隔离再计数；总览与列表避免重复轮询 |
| 创建 / 详情 | `POST /api/review-tasks`、`GET /api/review-tasks/{id}` | 创建与执行是两个步骤，保存成功而启动失败时保留任务 |
| 范围编辑 | `PUT /api/review-tasks/{id}/scope` | 仅开始前可编辑；服务端校验为准 |
| 执行 / 重跑 | `POST .../{id}/run`、`POST .../{id}/retry` | 全局串行执行；重跑得到新 ID，再显式启动 |
| 片段 / 原视频 | `POST .../{id}/events/{event_id}/preview`、`GET .../{id}/video` | 首次预览可能转码；409 忙碌仅做有界重试 |
| 人工判断 | `PATCH .../{id}/events/{event_id}` | 一次提交状态、reason 和 note；禁止跨条目读错输入 |
| 完成 / 导出 | `POST .../{id}/complete`、`GET .../{id}/report` | 未解决/覆盖不全时不能完成；保持服务端 HTML 导出格式 |
| 维护验证 | `POST /api/jobs`、`GET /api/jobs/{id}`、`POST /api/jobs/{id}/run` | 与正式任务分开，仅维护页使用 |

现有接口是能力盘点，不用于反向限定页面布局。新待办视图、媒资关联任务和任务摘要优先由已有数据组合；确有缺口时增加最小的兼容接口或字段，并补测试，不要求新产品照搬旧接口的一页一表结构。

接口返回多数仍为动态字典，直接生成 OpenAPI 类型未必覆盖实际任务与结果结构。第一阶段以接口响应和现有测试建立唯一的 `contracts.ts`，针对必要字段做边界归一化；未来完善后端响应模型后再整体转为生成类型，避免双份类型并存。

### 6.2 必须处理的接入细节

1. **串行执行**：若已有任务运行，显示“任务已创建，可稍后开始检查”；不自动重复 POST，也不把页面定时重试称为后台排队。
2. **提交结果未知**：创建/判断请求网络中断时，先重读确认结果；无法确认则告知用户，不无条件重发造成重复任务或历史记录。
3. **对象门禁**：生产只选已启用且有可用参考图的人物；验证使用当前后端允许的对象；停用对象不可选。保留 `ready_for_material` 等旧值，不为统一文案改写存量状态。
4. **照片恢复**：当前恢复到待验证，不自动提升为已启用。参考图“未停用”与人物“生产可用”分别展示。
5. **预览竞争**：预览请求序列化并有限缓存；优先当前条目，最多预取下一条；限制忙碌重试次数，失败后提供手动重试。
6. **播放定位**：现接口生成约 12 秒预览；接近片尾可能不足 12 秒。播放器以实际元数据为准，区分短片时间和原片偏移，只有来源偏移存在时才显示原片位置。
7. **无音轨/自动播放限制**：无音轨仍可复核；自动播放被浏览器阻止时显示播放入口，不判为检测失败。
8. **历史引用**：缺失参考快照时明确说明；如允许查看当前库照片，应标注其不是本次检查快照。
9. **修改已完成判断**：提供“修改判断”入口，说明保存后任务将重新进入待复核；服务端成功后同步列表和导出状态。
10. **错误分层**：字段错误贴近字段；首次加载错误展示重试；刷新失败保留旧内容；成功反馈简短。未知后端错误不直接暴露堆栈或文件路径。
11. **错误码缺口**：现接口常以自然语言 detail 报错。按操作和状态码做安全兜底；如需准确区分“任务占用”“参考图质量”等情况，只为相关接口增加兼容的稳定 code，保留原 status/detail，不在页面匹配报错字符串。
12. **上传进度**：上传传输进度与服务端校验分开；传输 100% 后仍显示“正在校验”，收到成功响应才显示已导入。中止传输不承诺已撤销服务端操作，恢复后通过媒资列表与去重结果核对。

## 8. 验证方案

### 8.1 业务回归矩阵

产品重构另需通过三项体验检查：审核员从工作台可直接进入具体待办；任务、媒资、人物详情之间能够按上下文往返；首次准备和日常复核各有清晰路径，不要求用户理解技术验证工具。不得以旧页面数量和控件数量一一对应作为验收标准。

| 场景 | 必须验证的结果 |
| --- | --- |
| 大盘与业务下钻 | 当前用途、指标口径、日期筛选和目标列表一致；处理、撤回、重跑后计数正确 |
| 趋势数据与旧记录 | 新任务日期真实持久化；旧日期缺失明确提示；不把导入时间当历史发生时间 |
| 全新工作空间 | 工作台首次准备引导出现，三种入口可用，无预先伪造的已完成结果 |
| 既有工作空间 | 不覆盖人物状态、照片状态、历史判断、备注和任务关系 |
| 重复导入 / 部分上传失败 | 不重复创建同一媒资；逐文件反馈，成功项不被失败项回滚 |
| 人物参考图 | 清晰图可导入；无脸/多脸/不合格图有可理解反馈；停用不影响旧快照 |
| 生产与验证 | 列表、总览、直达详情和返回导航用途一致；生产门禁无法绕过 |
| 创建成功、执行冲突 | 保留已创建任务，提供稍后启动；不重复创建或伪装运行中 |
| 复核保存 | 状态、原因、备注、历史一致；失败保留输入；重复点击被阻止 |
| 快速切片 / 返回 / 请求乱序 | 视频、人物、截图、备注和事件 ID 始终对应；迟到响应不覆盖当前片段 |
| 完成与撤回 | 未解决/覆盖不全禁止完成；修改已完成判断后恢复待复核 |
| 零候选 | 显示本次未发现候选，仍需按范围完成，不等同整片安全结论 |
| 重跑 | 创建新任务并关联旧任务，旧结果与历史不变 |
| 视频异常 | 转码忙、失败、文件缺失、无音轨、播放被阻止有各自可恢复反馈 |
| 任务刷新与重启 | 普通刷新不打断后台任务；服务重启后的状态按现有后端恢复策略展示，不承诺断点续算 |
| 导出 | 文件来自后端，与已保存用途、范围和人工记录一致 |
| 旧链接与资源 | 旧 hash 链接、参考图、证据图、默认视频、Range 请求可用 |

自动化测试使用独立临时状态；真实识别验证使用单独后端与独立状态/产物目录，不能复制状态后继续指向同一可写产物目录。仅浏览生产数据的视觉检查不提交判断。

### 8.2 测试层级

- 前端静态检查：TypeScript、Lint、生产构建、单一组件导入和主题令牌约束。只保留能发现实际回退的规则，避免检查代码字符串替代行为验证。
- 前端交互测试：以请求乱序、判断保存、草稿保留、任务创建部分成功、导入进度、门禁和焦点返回为重点。
- 后端回归：复用 `tests/test_product_workflow.py`、`test_review_workflow.py`、`test_workspace_import.py`、`test_showcase.py` 等；有兼容接口改动时补对应测试。
- 真实系统验收：现有已检测短片用于播放与记录流程；另新建至少一个多人物真实分析任务验证创建到导出闭环。接口 Mock 通过不能代替这一项。
- 独立真值和识别准召实验继续由现有算法验证协议管理，UI 迁移不产生新的准确率结论。

### 8.3 视觉与可访问性验收

检查桌面 1440×900、笔记本 1280×720、窄屏 768px 和手机 390px 宽度；完成一次 200% 缩放和完整键盘操作。窄屏可以纵向排列播放器和列表，不能让保存、返回或关闭按钮不可达。

对照 Aumai 的实际运行界面，在相同视口检查侧栏、页头、表格、弹窗、选择器、卡片与状态反馈。记录有意差异（例如复核专用布局和中文文案）。重点检查：焦点可见、弹窗焦点返回、Tab 顺序、状态播报、文字对比度、长任务名、省略内容可查看、滚动稳定、选中后 hover 仍可辨识。

### 8.4 性能验收

使用现有短片与扩展的合成列表分别测量，记录测试机器与数据规模：

- 列表筛选/分页交互目标在 200ms 内反馈；超过时定位数据量或渲染问题，再决定服务端分页或虚拟列表。
- 片段切换立即显示当前条目的海报和准备状态；预览生成时间单独记录，不把转码耗时归入 UI 响应。
- 已缓存短片点击到可播放目标 1 秒内；首次转码如超出目标，保留加载和恢复反馈，不显示虚假倒计时。
- 后台轮询不重绘播放器、不清空草稿、不移动焦点；页面退出时停止不再需要的请求。
- 媒资页初次加载不预读所有视频，复核页最多播放一个视频并有限预取。

这些是待验证的体验目标，不是当前实测结果。性能优化以测量为依据，不提前引入复杂状态库、播放器框架或批量预转码。

## 9. 切换、兼容与回退

### 9.1 切换前

1. 确认分析任务空闲，保留当前前端版本与资源清单。
2. 停止写入后备份本次运行 profile 对应的状态与关联产物；原始文件保持原位。
3. 从锁文件构建到暂存目录，核对参考图数量/哈希、脚本资源、API 和播放地址。
4. 在独立测试环境完成迁移验收，记录版本、环境、已通过项及遗留项。
5. 更新默认静态入口，启动单个服务；通过版本标识确认访问的是新构建。

### 9.2 切换后检查

核对当前用途与列表、任一历史任务/参考快照、短片播放、已保存原因备注、对象停用状态及导出。新产生的审核写入按日常业务保留。

### 9.3 回退规则

| 问题 | 回退方式 |
| --- | --- |
| 页面、路由、样式或组件异常 | 切回已保留的旧静态构建，沿用最新状态文件 |
| 静态照片或资源丢失 | 恢复对应资源及 URL，检查构建复制清单；不重置人物库 |
| 请求适配或兼容 API 异常 | 回退对应代码后重新启动单个后端，保留业务数据 |
| 数据损坏迹象 | 停止写入，保留异常文件与最新副本，核对后专项恢复；不直接覆盖为迁移前旧状态 |

正常回退不恢复过时的数据库/JSON 快照，避免丢失切换后审核员已提交的判断。新增媒资标识等字段采用兼容扩展，旧读取方式仍能工作；如需改变已有字段或持久化结构，应补充迁移、兼容及恢复方案后执行。
