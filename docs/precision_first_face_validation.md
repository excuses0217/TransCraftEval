# 精度优先全库人脸检索验证

验证日期：2026-09-20

## 验证问题

本轮验证面向“事先不知道视频中有哪些目标人物、需要对完整敏感人物库进行 1:N 检索”的产品场景，重点回答三个问题：

1. 当前单帧候选规则为什么产生大量不在演员表中的姓名；
2. 开集拒识和连续轨迹门控能否降低跨片误报；
3. 相邻片段自动归并能压缩多少审核事件，并且如何避免把间隔画面伪装成连续出镜。

演员表仅作为代理标签：演员表内候选不等于正确人脸，演员表外候选也可能包含客串或资料遗漏。本文所有“精度”相关数据均为代理指标，不替代独立盲标。

## 数据范围

- 5 部本地全片：《一江春水向东流》《上甘岭》《五朵金花》《东方红》《乡音》；
- 合计约 10.02 视频小时；
- 14 个人物对象；
- 现有全库任务产生 3,179 个人物事件；
- 另选取 23 个 6 秒窗口，以 0.25 秒间隔重新扫描：13 个演员表内或已知正样本窗口、10 个跨片高分硬负窗口。

复扫仍使用现有 YuNet + SFace，不通过更换模型掩盖决策层问题。

## 第一阶段：全片事件离线重算

| 策略 | 事件数 | 演员表内候选 | 跨片候选 | 跨片候选/小时 | 应出现组合覆盖 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 当前基线：0.35、单帧即可 | 3,179 | 2,375 | 804 | 80.22 | 10/10 |
| 开集门槛：0.50、分差 0.03 | 429 | 429 | 0 | 0 | 9/10 |
| 短轨迹：0.55、3 帧、分差 0.08 | 87 | 87 | 0 | 0 | 8/10 |
| 自适应轨迹 | 117 | 117 | 0 | 0 | 10/10 |
| 精度轨迹：0.60、3 帧、分差 0.08 | 28 | 28 | 0 | 0 | 7/10 |
| 严格轨迹：0.65、3 帧、分差 0.10 | 12 | 12 | 0 | 0 | 5/10 |

自适应轨迹采用两个可解释的确认入口：

- 短轨迹：最高分不低于 0.55、至少 3 个支持帧、身份分差不低于 0.08、多参考图确认分不低于 0.45；
- 长轨迹：最高分不低于 0.46、至少 8 个支持帧、身份分差不低于 0.12、多参考图确认分不低于 0.46。

第二个入口不是“连续帧越多就可以无限降低阈值”。它仍要求更大的身份分差和参考图确认分，只用于找回稳定但因老片画质导致单帧分数偏低的轨迹。

## 第二阶段：高帧率窗口复扫

| 策略 | 正样本代理窗口保留 | 跨片硬负窗口误保留 |
| --- | ---: | ---: |
| 当前基线 | 13/13 | 9/10 |
| 开集门槛 0.50 | 11/13 | 0/10 |
| 短轨迹 | 11/13 | 0/10 |
| 自适应轨迹 | 13/13 | 0/10 |
| 精度轨迹 | 8/13 | 0/10 |
| 严格轨迹 | 4/13 | 0/10 |

代表性现象：

- 杨丽坤窗口最高分约 0.496，但连续支持 19 帧；
- 邓玉华窗口最高分约 0.476，但连续支持 17 帧；
- 两者会被固定 0.50 门槛漏掉，但可被自适应长轨迹入口保留；
- 《五朵金花》中一段被错误候选为上官云珠的画面连续支持 15 帧、最高分约 0.488，但多参考图确认分只有约 0.414，因此被自适应规则拒绝；
- 《牧马人》三个朱时茂已知窗口均被自适应规则保留。

这说明连续轨迹的正确用途是降低随机单帧波动、补充弱画质证据；身份确认仍必须检查绝对分数、Top-1/Top-2 分差和参考图一致性。

## 片段归并实验

当前基线事件按同一人物和时间间隔归并：

| 最大间隔 | 归并后事件 | 压缩比 |
| ---: | ---: | ---: |
| 1.5 秒 | 2,643 | 1.20 |
| 3 秒 | 1,887 | 1.68 |
| 5 秒 | 1,614 | 1.97 |

自适应轨迹已经在执行阶段合并了大部分连续帧，因此 3 秒二次归并只从 117 条减少至 113 条。产品应区分两级关系：

1. 同一人脸轨迹、间隔不超过约 1.5 秒：合并为连续片段；
2. 同一人物、镜头切换后间隔约 1.5～5 秒：归到同一出镜事件，但保留每个子片段的真实起止时间。

不应把多个子片段渲染成一条无间断时间区间。

## 当前结论

这组数据支持把生产候选逻辑从“单帧最高分超过 0.35”改为以下流程：

```text
全库 Top-K 召回
  → 绝对分数与未知人物拒识
  → Top-1 / Top-2 身份分差
  → 多参考图确认分
  → 同一人脸连续轨迹聚合
  → 短轨迹 / 长轨迹双入口
  → 连续片段合并与跨镜头事件归组
```

自适应轨迹是当前最值得进入下一轮盲标的候选策略。它在现有代理数据中同时保留 10/10 应出现人物—媒资组合，并将 804 条跨片候选降为 0；在 23 个高帧率窗口中保留 13/13 正样本代理，同时拒绝 10/10 跨片硬负源身份。

## 不能据此宣称的内容

- 不能宣称正式精确率为 100%；演员表内可能框中了同片其他演员；
- 不能宣称正式召回率；窗口来自旧系统候选，没有对全片所有真实出镜做盲标；
- 刘玉茹和陶金各有同片剧照参考，存在参考素材同源带来的分数优势；
- 多数人物不足 3 张独立参考图，人物级阈值尚不能稳定校准；
- 当前事件保存的是最佳帧分数，还没有实现轨迹中位数、分位数和逐帧身份投票。

## 下一轮验收

1. 对 23 个窗口隐藏模型身份后完成人工轨迹盲标；
2. 每位人物补足至少 3 张不同来源、不同姿态或时期的参考图；
3. 为每个人物收集同片其他演员和相似脸硬负样本，校准对象级阈值；
4. 在执行器中保存逐帧分数，比较最高分、中位数、75 分位数和身份投票；
5. 用不同影片做校准集和测试集，报告事件精确率、未知人脸误认率、每小时误报和候选召回率。

## 视频轨迹模型 A/B 补充验证

在相同的 23 个窗口上固定 YuNet 检测、五点对齐、轨迹组装和 0.25 秒采样，
只替换身份编码器，对比 SFace 与 ArcFace。轨迹决策新增以下证据：

- 帧级 Top-1 身份投票比例；
- 目标身份分数中位数与低四分位；
- 前半段与后半段身份一致性；
- 相邻帧人脸特征的轨迹内部一致性；
- 短轨迹强证据、长轨迹持续证据两条独立入口。

固定双入口候选策略的代理结果如下：

| 编码器 | 正样本代理召回 | 强负源身份进入召回区 | 强负源身份自动通过 | 需人工轨迹 | 进入门控后的代理人工降幅 | 实时系数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| SFace | 13/13 | 5/10 | 0/10 | 12 | 55.6% | 0.2801 |
| ArcFace | 13/13 | 1/10 | 0/10 | 4 | 82.6% | 0.6596 |

ArcFace 的轨迹正负分数间隔为 0.08451，SFace 为 0.03083；ArcFace 的低四分位
间隔为 0.03214、Top-1/Top-2 分差间隔为 0.16214，而 SFace 对应两项已经发生
重叠。这说明 ArcFace 在当前老片样本上的自动拒识余量更大，虽然 CPU 推理约慢
2.35 倍，但仍快于实时播放。

按影片留一的单入口检查中，ArcFace 自动候选保留 11/13 个正样本代理，强负源
身份为 0/10；漏掉的两个样本都是只有约 5 帧的朱时茂短片段。这一失败直接支持
双入口设计：短轨迹不能套用长轨迹的最低帧数，但必须要求更强的绝对相似度、
身份分差和参考图一致性。

当前推荐路线是 `YuNet → ArcFace → 人脸轨迹 → 质量加权多帧融合 → 开集拒识 →
短/长双入口 → 连续事件归并`。QMagFace 官方实现需要旧版 PyTorch 环境，且代码
采用 CC BY-NC 4.0；在 ArcFace 已获得明显分离优势的情况下，现阶段接入它的产品
ROI 不高，可先用现有清晰度、脸部尺寸、检测置信度做质量加权。

该结果仍不能直接开启生产自动确认：窗口由历史候选选出，演员表也只是代理标签。
上线门限必须通过现有盲标视频完成独立身份标注后锁定，并报告未知人脸误认率、
事件精确率、候选召回率和每视频小时人工复核数。

### 已完成人工记录的交叉检查

系统中第一批盲标任务已有 26 条人工操作记录。按“同一六秒窗口、同一人物、同一
结论”去除旧运行器造成的重复帧事件后，得到 19 个人物—窗口标签：17 个确认、
2 个排除，另有 12 条旧事件尚未处理。

| 编码器 | 确认标签原始召回 | 确认标签进入召回门 | 确认标签进入自动门 | 排除标签进入自动门 | 需二次确认的分歧标签 |
| --- | ---: | ---: | ---: | ---: | ---: |
| SFace | 17/17 | 16/17 | 11/17 | 0/2 | 1 |
| ArcFace | 17/17 | 14/17 | 13/17 | 0/2 | 3 |

ArcFace 对已确认人物的原始 Top-1 轨迹召回为 17/17，自动门覆盖 13/17，高于 SFace
的 11/17；已排除的两个标签均未进入 ArcFace 原始候选。但排除样本只有两个，且这
批标签原本由 SFace 候选触发，存在候选选择偏差，不能据此宣称自动区精确率为
100%。三个 ArcFace 分歧项应先做二次盲标，尤其不能为了迁就可疑标签直接降低自动
门限；正确做法是把它们留在人工区。
