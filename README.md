# 映鉴：本地媒资审核工作空间

当前工作流为“选择媒资与核查人物 → 系统检查 → 逐条复核疑似片段 → 完成并导出审核记录”。任务页提供实时进度、待办与历史结果；复核页提供画面、人物参考照片、原片定位和处理备注。确认、排除、留待复核与撤回均保存到本机。

人物库支持新增、编辑和导入本地参考照片。新任务使用多人物、多参考图共同检索，并按短时空间及外观连续性整理候选；机器结果不会直接替代人工身份判断。左侧可切换生产审核与算法验证用途；维护工具另有技术验证入口。

当前可实际执行的检测通道仅为人脸检索。审核对象库和审核任务会持久化到本机 `data/media_review_state.json`；OCR、ASR、视觉语义和 LLM 只有接入后才会显示为任务通道，不会用占位结果伪造检测结论。

它是可运行的本地产品原型，已经采用完整 SaaS 信息架构；当前仍不应用于执法、处分或其他高风险自动决策。

## 一键启动完整本地工作空间

macOS 双击项目根目录的 **`start.command`**，或在终端执行：

```bash
./scripts/start_showcase.sh
```

入口为 <http://127.0.0.1:8770/?workspace=validation#/overview>。前端、后端、识别服务由同一个本地进程提供，不需要启动 Node、数据库或云端 API。默认打开算法验证大盘，可下钻到待办、媒资和已检查片段，也可选择人物新建真实任务。

首次使用会显示初始化引导：可导入内置素材、选择自己的本地 MP4，或暂不导入。已有工作空间不会被清空或重复初始化；日后可随时从媒资库点击“导入素材”。没有内置素材包也能启动并导入自己的视频。本地视频按内容去重，复制到系统目录后持久保存。

- 默认素材包 `showcase_bundle/`：6 部本地影片的 12 个短片段，14 位人物、24 份参考素材，12 个真实检查任务及 82 条待人工复核线索。
- 影片包括《牧马人》《一江春水向东流》《上甘岭》《东方红》《乡音》《五朵金花》。短片段约 17–24 秒，按历史候选集中程度选取后重新检测，不是独立准确率/召回率测试集。
- 人物照片的停用状态原样保留；默认包的照片、线索与参考快照均存储在本地。不联网下载视频，也不依赖整部电影继续存在。
- 默认包只读使用；用户确认导入后，条目加入 `data/showcase/state.json`，重启保留修改与审核记录。重复导入只补缺少的条目，不覆盖已有记录。新任务输出在 `artifacts/showcase/`，导入视频在其 `media/` 子目录。
- 原整片工作空间继续使用 `data/media_review_state.json`，与 8770 演示环境独立。原片保留在本机 `媒资/`，不纳入 Git。
- 重复启动会打开已有演示服务；端口被其他服务占用时提示错误，不停止其他进程。默认只监听本机。

运行要求 Python 3.12+。脚本会跳过版本不满足要求的旧环境，优先复用项目虚拟环境或本机 `transcrafteval` Conda 环境。首次缺少依赖/模型时需要联网；配置完成后日常演示不需要外网。可用 `FACE_WATCH_PYTHON` 指定解释器、`FACE_WATCH_PORT` 修改端口、`FACE_WATCH_NO_BROWSER=1` 禁止自动打开浏览器。按 Ctrl+C 停止，记录仍保留。

换机器时请复制完整项目和 `showcase_bundle/`；模型在 `models/`，可一起复制以避免重新下载。代码分支本身不代替本地素材包，尚未提交的文件也不会随 Git 分支自动分发。不要复制 `.env`、API 密钥或个人审核状态。素材仅限已获授权的本地测试，对外分发前需另行确认使用权限。

`scripts/build_showcase.py` 用于维护人员首次构建素材包，会从本地已有任务选取不重叠窗口，转码并重新执行多人物检查。正常启动不执行此脚本；已有完整包时拒绝覆盖。

## 原工作空间启动（保留兼容入口）

```bash
git clone <repository-url>
cd TransCraftEval
./scripts/run_prototype.sh
```

旧脚本零参数使用 `examples/sample.mp4`、`examples/reference.jpeg` 及标签“目标人物（老许）”，默认端口为 8765，直接使用 `.venv`，不是完整默认包入口。需要 Python 3.12+；首次安装依赖和模型需要网络。该入口与既有 8766 原环境共用状态文件，不要并行启动写入；完整演示请使用上方一键入口。

也可以覆盖任意默认值：

```bash
./scripts/run_prototype.sh '/path/to/video.mp4' '/path/to/reference.jpg' '人物名称' 8765
```

如果希望分步启动：

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[test]'
./scripts/download_models.sh
FACE_WATCH_VIDEO='/path/to/video.mp4' \
FACE_WATCH_REFERENCE='/path/to/reference.jpg' \
FACE_WATCH_PERSON='人物名称' \
.venv/bin/face-watch --host 127.0.0.1 --port 8765
```

## 当前实现范围

- SaaS 产品框架：审核大盘、审核工作台、任务中心、媒资中心、审核对象库、审核结果和独立技术验证入口；生产审核与算法验证按任务用途分开。
- 审核大盘：当前积压、任务趋势、任务状态、人工判断分布、近期完成和需要关注任务；旧任务缺少日期时不会伪造趋势数据。
- 审核对象库：人物库、文本规则库、场景与行为库分开管理；人物须补齐参考照片、记录验证结论后才能启用到生产审核，素材变更会使验证失效。
- 审核任务：分步选择真实本地媒资和多个人物，可在开始前编辑范围，查看真实执行进度、失败状态、重跑关系和审核统计。
- 真实人脸检索：可从本地视频和参考图生成候选时段与证据帧。
- 专注复核：自动准备可播放短片、并列展示当次参考快照，以结构化原因和备注确认、排除或留待复核；支持快捷键、自动进入下一条和窄屏操作。
- 审核结果：按任务保存人物结论、确认片段、完整处理记录及完成版本快照；重新打开必须填写原因，旧版本保留不覆盖。
- 任务结果与复核历史会持久化；历史实验可以通过 `scripts/import_validation_results.py` 在服务停止时导入，页面明确标注抽检范围。
- 待接入：OCR、ASR、镜头切分、视觉语义召回、跨模态证据归并、LLM 研判，以及多人账号、权限、任务分派与团队数据库。

## 已导入的公开参考素材

完整默认包保留当前人物库的 14 位人物及 24 份参考素材，包括已停用的低质量照片。每份素材可查看本地预览及当前状态；停用照片不参与新任务，不因打包而自动重新启用。照片数量不表示已完成跨片可用性标定，机器匹配也不能单独形成审核结论。

所有进入审核任务或人物参考集的媒资都必须是本机已授权文件。外部页面可作为人工查找来源的线索，但系统不会下载或分析外部在线播放地址。

实际部署前仍应逐份确认版权、肖像权、处理授权、保留期及所在地区适用要求。

## 人脸检索实现组成

- `FastAPI`：任务创建、异步进度和结果 API
- OpenCV Zoo `YuNet`：人脸检测和五点定位
- OpenCV Zoo `SFace`：对齐后的人脸特征
- 精确余弦相似度：单个关键人物无需近似向量索引
- 多人物、多参考图候选检索和短时关联；所有候选均需人工复核，不自动确认身份
- React + TypeScript 构建的本地 SaaS 前端：生产运行无需 Node.js 或云端服务

模型文件由 `scripts/download_models.sh` 下载并校验 SHA-256，不提交到仓库。证据输出位于 `artifacts/`。

仓库中的电影片段和人物照片仅作为原型技术测试样例；用于其他环境或对外分发前，请确认拥有相应使用权限。

## 已知边界

- 本机状态保存为 JSON 文件，适合单机原型；有线索复核历史，但尚未提供多人账号、权限、防篡改合规审计或服务端数据库，不应直接公网部署。
- 当前按时间间隔聚合候选帧，尚未接入正式的人脸 tracker 和镜头切分。
- 单张现代正脸照片与 1982 年影片存在显著年龄域差异；低质量、侧脸和背脸线索必须人工复核。
- 相似度不是身份概率，精选片段和既有实验未构成完整独立真值；更换人物、视频来源或模型后需重新验证和标定。
- 人脸照片和 embedding 属敏感生物识别数据；实际部署前需完成授权、保留期、删除、审计和当地法规评估。
